## 3. CI/CD Pipeline — ⚠ Needs Manual Action

**What was already in place:** `.github/workflows/ci.yaml` already ran on push/PR to `main`,
installed dependencies, compiled + tested the contract, and type-checked/linted the API, CLI, and
UI packages.

**What was missing and has now been added:** the workflow did not explicitly build the frontend.
A `Build secretbid-ui` step (`npm run build`, working directory `secretbid-ui`) has been added
after the existing UI lint/typecheck step. The workflow already fails the job (default GitHub
Actions behavior) if any step — install, compile, test, or build — fails, since no step uses
`continue-on-error`.

The pipeline now does, in order: install dependencies → compile the Compact contract → run
contract tests → typecheck/lint API, CLI, UI → build the UI (which also depends on the contract's
compiled `managed/` output). This satisfies the Level 3 requirement's step list.

**Pre-existing lint failures fixed:** while verifying this workflow would actually pass, `npm run
lint --workspace=secretbid-ui` was found to fail on the current `main` branch (162 Prettier/ESLint
errors, unrelated to this audit's other changes) — meaning the CI pipeline would have failed on
its own UI lint step even before any of today's edits. These were auto-fixed via `eslint --fix`
(pure formatting; one unescaped-apostrophe fix in `CreateAuctionPage.tsx`) and re-verified: lint,
typecheck, and build now all pass locally for every workspace.

**Manual action required:**
1. Commit and push these changes, then confirm the workflow actually goes green on GitHub Actions —
   this report does not fabricate a run result; you need to watch the Actions tab yourself.
2. Once you have a passing run, add a status badge to the top of `README.md`, e.g.:
   ```
   [![CI](https://github.com/<your-org>/<your-repo>/actions/workflows/ci.yaml/badge.svg)](https://github.com/<your-org>/<your-repo>/actions/workflows/ci.yaml)
   ```
   Replace `<your-org>/<your-repo>` with the real GitHub path. Do not paste a badge until you know
   the workflow name/path is correct and a run exists, or the badge will show "no status."

## Changes Made During This Audit

1. **`.github/workflows/ci.yaml`** — added an explicit `Build secretbid-ui` step so the pipeline
   builds the frontend, not just lints/typechecks it.
2. **`README.md`** — added a new **Privacy Model** section (What an Observer CAN / CANNOT Learn),

     has an accessible name (previously relied on visual proximity to the dialog title only).

     the CI lint step actually pass on `main`.

6. **No redesign.** Landing page layout, visual design, and component structure are unchanged;
